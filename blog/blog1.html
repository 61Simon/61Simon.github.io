How I Built AURELIA — A Luxury Automotive Atelier

Lessons from building a premium detailing site — SPA routing without a framework, before/after sliders, gallery filtering, and the design system behind the gold-on-obsidian aesthetic.

When I started building AURELIA, I had one specific question in mind: can you make a website feel expensive without using a single framework?

No React, no Framer Motion, no GSAP. Just HTML, CSS, and vanilla JavaScript. The result is a luxury automotive detailing atelier that looks like it belongs on a premium brand's website — with SPA routing, interactive components, and a dark gold aesthetic. Here's how I built it.

The Challenge

The brief I set for myself was strict:

  • A luxury automotive brand feel — gold on obsidian, serif headlines, generous whitespace
  • Five content sections managed as a single-page app
  • A before/after slider for paint correction
  • A filterable portfolio gallery with a fullscreen lightbox
  • Form validation with floating labels
  • Mobile-first responsive design
  • No build step — deployable as static files

Luxury brands are tricky. Everything has to feel intentional. A misplaced border-radius or a slightly wrong easing curve can make a "premium" site look cheap. So most of the work was in the details.

The Design System

The whole site is built on a small set of CSS custom properties. Two font families: Playfair Display for headlines (serif, editorial), Inter for everything else. This combination is the closest you can get to "silent luxury" without custom typefaces.

The gold is #C5A880 — a muted, desaturated gold. Not #FFD700. Bright yellow-gold screams "cheap"; muted gold whispers "expensive". This single color decision does most of the heavy lifting.

:root {
    --bg-base: #050505;
    --bg-surface: #0a0a0a;
    --gold: #C5A880;
    --text-main: #F5F5F5;
    --text-muted: #888888;
}

Everything else — cards, borders, buttons — inherits from these five variables. Change the gold, and the entire site changes with it.

SPA Routing Without a Framework

All content sections live in one HTML file. The router is about 20 lines:

const router = {
    navigate(targetId) {
        document.querySelectorAll('.section').forEach(sec => {
            sec.classList.remove('active');
            sec.style.display = 'none';
        });
        
        const target = document.getElementById(targetId);
        if (target) {
            target.style.display = 'block';
            setTimeout(() => { target.classList.add('active'); }, 50);
        }
        
        document.querySelectorAll('.nav__link').forEach(link => {
            link.classList.toggle('active', link.getAttribute('data-target') === targetId);
        });

        window.scrollTo({ top: 0, behavior: 'smooth' });
    }
};

The key insight: display: none/block for hard visibility, and a small setTimeout to allow the opacity transition to actually run. Without the timeout, the browser would batch the class change with the display change and the fade would never play.

The active class handles the opacity fade — using cubic-bezier(0.16, 1, 0.3, 1), my favourite easing curve. It starts fast and settles into stillness. Feels "weighty" without feeling slow.

Interactive Components

Before/After Slider

This was the most fun component. The trick is to use clip-path on the "after" image:

.ba-after { 
    clip-path: inset(0 0 0 50%); 
}

The inset(0 0 0 X%) reveals the image from the right side. Move the handle, and you move the reveal. Mouse and touch events are handled — no library needed.

Portfolio Filtering

Filtering the gallery is done in ten lines:

filterBtns.forEach(btn => {
    btn.addEventListener('click', () => {
        filterBtns.forEach(b => b.classList.remove('active'));
        btn.classList.add('active');
        const filter = btn.dataset.filter;

        galleryItems.forEach(item => {
            const match = filter === 'all' || item.dataset.category === filter;
            item.classList.toggle('hidden', !match);
        });
    });
});

Each gallery item has a data-category attribute. When a filter is clicked, non-matching items get .hidden (which sets display: none). That's it.

Image Modal

Clicking a gallery item opens a fullscreen lightbox showing the high-res version. The full-res URL is stored in the same data-src attribute. Setting document.body.style.overflow = 'hidden' prevents background scrolling — a small detail that most custom modals forget.

Floating Label Form

The contact form uses floating labels — the label sits inside the input until you type, then moves up. This is done with :placeholder-shown and a fake placeholder:

.form-control::placeholder { color: transparent; }

.form-control:focus ~ .form-label,
.form-control:not(:placeholder-shown) ~ .form-label {
    top: -10px; 
    font-size: 0.7rem; 
    color: var(--gold);
}

The trick: set the placeholder to a single space. Now :placeholder-shown works correctly, and the label transitions into position as soon as you type.

Reveal Animations

Every section fades in as you scroll. This is done with an Intersection Observer. The unobserve() call is important — once an element has revealed, there's no need to keep watching it. Saves CPU.

What I'd Do Differently

  1. Add URL state to the router. Right now navigating between sections doesn't update the URL. If I did it again, I'd use history.pushState() so users could bookmark specific sections.
  2. Lazy-load portfolio images. Some of them are 1600px wide. loading="lazy" should be on every gallery image.
  3. Add reduced-motion support. Some users get motion sickness from animations. @media (prefers-reduced-motion: reduce) should disable all transitions.
  4. Split the CSS. 1500 lines in one <style> tag is a lot to scroll through. Even without a build step, I could use multiple <link> tags.

💡 Lesson learned: You don't need a framework to build a premium-feeling website. AURELIA is pure HTML, CSS, and JavaScript — no dependencies, no build step, deploys anywhere as static files.

Final Thoughts

AURELIA proved to me that restraint is a design skill. Every animation, every color, every typeface is a choice — and the best luxury sites are the ones that choose less.

The framework question is really: what problems are you solving? For a five-section marketing site with interactive components, vanilla JS is perfect. For a data-heavy app with complex state, React is the right tool.
